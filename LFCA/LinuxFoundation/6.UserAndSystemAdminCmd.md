# 6. USER AND SYSTEM ADMINISTRATION COMMANDS

## Introduction
### Chapter Overview

When using or administering Linux systems, commands are used all the time, for functions like changing a directory or folder, and listing the files in a directory. Using the command line provides clean and concise methods to query, display, or change the operation of a system. 

The Graphical User Interface (GUI) is very useful, providing a bridge to new things, but the GUI is usually created after the commands have been in place for some time.


### Learning Objectives
 
By the end of this chapter, you should:
- Have a good understanding of Linux commands and options.
- Know common Linux system administration commands.
- Know common network administration commands.
- Know common user administration commands.

## Linux Commands
### Why Are There So Many Commands?

People new to Linux often ask why there are so many commands, especially when some of the commands do essentially the same thing. The literally thousands of commands possible in a Linux system can be very intimidating. Here’s some good news: No, you don’t need to know all of the commands and options to those commands. When you first start out, you really only need a few commands to do your job. But do try to learn new commands and options at least once a week. After a few months, you will be surprised by how many commands and options to those commands you will know.

Why do some of them seem to do the same thing as other commands? In some cases, there may be subtle differences. Often, the output is slightly different. Sometimes, one command may be more efficient in terms of CPU, memory or I/O than other commands.

### Using a Text Terminal on a Graphical Desktop

A [terminal emulator](https://en.wikipedia.org/wiki/Terminal_emulator) program emulates (simulates) a standalone terminal within a window on the desktop. By this, we mean it behaves essentially as if you were logging into the machine at a pure text terminal with no running graphical interface. Most terminal emulator programs support multiple terminal sessions by opening additional tabs or windows.

By default, on GNOME desktop environments, the **gnome-terminal** application is used to emulate a text-mode terminal in a window. Other available terminal programs include:

- [xterm](https://en.wikipedia.org/wiki/Xterm)
- [Konsole](https://konsole.kde.org/) (default on KDE)
- [Terminator](https://terminator-gtk3.readthedocs.io/en/latest/#)

### Launching a Terminal Window

To open a terminal on any system using a recent GNOME desktop, click on **Applications > System Tools > Terminal or Applications > Utilities > Terminal**. If you do not have the **Applications** menu, you will have to install the appropriate ```gnome-shell-extension``` package and turn it on with ```gnome-tweaks```.

You can also hit ```Alt-F2``` and type in either ```gnome-terminal``` or ```konsole```, whichever is appropriate. Because distributions have had a history of hiding the methods for opening up a command line terminal, and the place in menus may vary in the desktop GUI, it is a good idea to figure out how to "pin" the terminal icon to the panel, which might mean adding it to the **Favorites** grouping on GNOME systems.

### Command Syntax

A command usually has three parts, separated by a space.

- **Command**

    This is the name of the program you are executing (e.g., ```ls```, ```ps```).

- **List of options**

    The command may be followed by one or more options (or switches) that modify what the command may do. Options usually start with one or two dashes, in order to differentiate them from arguments, which represent what the command operates on.

    Options come in four flavors:

    - UNIX options - these are single-letter preceded by a dash (```-```). They may be grouped together (e.g., ```-lhi```)
    - BSD options - these are single-character, with NO preceding dash; may be grouped together (e.g., ```aux```)
    - GNU long, preceded by a double dash (```--```); generally, a word is the option (e.g., ```--all```)
    - No designation, just a list of words or short forms (e.g., ```connection show```)

    However, plenty of commands have no options, no arguments, or neither. In addition, other elements (such as setting environment variables) can also appear on the command line when launching a task.

    You can see some examples in the table below:

    |COMMAND|OPTIONS|ARGUMENTS|
    |---|---|---|
    |```ls```|```-l```|/home/student|
    |```grep```|```-i localhost```|/etc/hosts|
    |```df```|```-h```|/|
    |```man```|```-K```|cifs|
    |```find```|```/ -iname```|lvm|
    |```mount```|```-t ext4```|/dev/sdb1 /opt|





### sudo

```sudo``` allows users to run programs using the security privileges of another user, generally root (superuser).

When running on Ubuntu and some other recent distributions, sudo is already always set up for you during installation. On other Linux distributions, you will likely need to set up sudo to work properly for you after the initial installation.

When using sudo, by default you will be prompted to give a password (your own user password) at least the first time you do it within a specified time interval. It is possible (though very insecure) to configure sudo to not require a password or change the time window in which the password does not have to be repeated with every sudo command.

### The man Command

When starting to learn about commands, one of the very first commands to learn is the ```man``` command, which is used to display the user manual of any command that can be run on the terminal:


```shell
$ man

What manual page do you want?
```

```man``` is the most often used utility for locating and gathering information on the system itself. It is easy to use and gives the most accurate information, as it describes the actual system; whereas, searching on the Internet can be misleading. Experienced users employ ```man``` every day in their work.

The ```$``` preceding the command in the above example is a convention used to say the command is going to be executed as a "regular user", not "root" as the admin user.

The command is next; in the example provided, ```man``` is the command.

The table below shows the section numbers of the manual followed by the types of pages they contain:

|SECTION NUMBER |	DESCRIPTION|
|---|---|
|**1**|	Executable programs or shell commands
|**2**|	System calls (functions provided by the kernel)
|**3**|	Library calls (functions with program libraries)
|**4**|	Special files (usually found in ```/dev```)
|**5**|	File formats and conventions (e.g., ```/etc/passwd```)
|**6**|	Games
|**7**|	Miscellaneous, including macro packages and conventions. E.g., **man(7)**, **groff(7)**
|**8**|	System administration commands (usually only for root)
|**9**|	Kernel routines [Non standard]


Manual pages consist of several sections. The list of section names is not fixed, and not all section names may be available on a manual page. Conventional section names for man pages may include:


|SECTION NAME	| DESCRIPTION|
|---|---|
|**NAME**|	The name of the man page in a 1-line format
|**SYNOPSIS**|	Shows the command syntax and available options and arguments for the command|
|**CONFIGURATION**|	Configuration details. Select a different configuration file for the command|
|**DESCRIPTION**|	Detailed explanation of what the command does|
|**OPTIONS**|	List of options available for a particular command, and how they change its behavior|
|**EXIT STATUS**|	List of possible exit status values for a command or program, and the conditions that cause these values to be returned. For example, and exit status value of 0 means the command was completed without errors; any other value indicates an error from the command|
|**RETURN VALUE**|	List of values returned to the user, and the conditions that cause these values to be returned. Usually, same as exit status|
|**ERRORS**|	List of error codes in the output and their meaning. Should be in alphabetical order|
|**ENVIRONMENT**|	List of all environment variables that affect the command or program and how they affect it|
|**FILES**|	List of files the command or program uses (e.g., configuration files, startup files, etc.)|
|**CONFORMING TO**|	Description of standards or conventions that relate to the command described by the manual page|
|**NOTES**|	Miscellaneous notes|
|**BUGS**|	List of limitations, known defects or inconveniences|
|**EXAMPLE**|	One or more examples showing how the command, or program, or file is used|
|**AUTHORS**|	List of authors of the documentation or program|
|**SEE**| ALSO	Comma-separated list of related man pages, additional documentation, etc.|


A short command usage, along with a short list of options is typically available with -? or --help options:
```shell
$ man -?
or
$ man --help
```

### systemctl Command

```systemctl``` is a new Linux tool used to control the [systemd](https://man7.org/linux/man-pages/man1/systemd.1.html) system and service manager, allowing you to start, stop, or restart a service, get information about system units and about the state of the services in your system. A service or a unit is a resource or an object that systemd is aware of and knows how to address. ```systemctl``` uses the following syntax:

```shell
systemctl [OPTIONS...] COMMAND [UNIT...]

systemctl start nginx
```

|COMMAND        |OPTION         |COMMAND        |UNIT   |DESCRIPTION|
|---            |---            |---            |---    |---|
|```systemctl```|	            |               |all    |List the status of all systemd elements|
|```systemctl```|	            |```start```    |unit   |Start the named unit now
|```systemctl```|	            |```stop```     |unit	|Stop the named unit now
|```systemctl```|	            |```enable```   |unit	|Start the named unit on next system start
|```systemctl```|   	        |```disable```  |unit	|Stop the named unit from starting on system start
|```systemctl```|```--all```    |```status```   |       |List the status of all units in a tree format
|```systemctl```|```--now```    |```enable```   |unit   |	Start the unit now and set the unit to start on next system start
|```systemctl```|```--failed``` |	            |       |List the failed units|
