## Linux Installation
- **Installation Choices**

    A successful system administrator will be able to install Linux on either a bare metal machine, or a virtual machine. The installation process is basically the same for both virtual and physical machines. The differences and virtual environment configuration are not covered in detail in this course.

    There are a variety of ways to install Linux for this course, if you do not already have a working installation. You can install directly on your computer, which will give you the best performance and most satisfying experience. If you already have an operating system installed (such as Microsoft Windows or MacOS), you may keep that in place while you configure a “dual boot” system. This can, however, be tricky, and it takes some experience to avoid profoundly messing up your system.

    Thus, for most students who need to do a fresh install, the use of a freely available hypervisor, such as ___VMware Workstation Player___ or ___Oracle VirtualBox___ is the method of choice and is rather easy to implement. The hypervisor runs on the host operating system, and Linux is installed as a guest virtual machine (VM).

    Whether you do a physical or virtual machine installation, only the beginning of the procedure is different; once the initial setup is complete, the experience is the same. We will show in some detail the use of VMware Workstation Player in order to be concrete. It is easy enough to replicate the equivalent steps with Oracle VirtualBox.

- **Using AWS or WSL/WSL2**

    As we have noted, there are various alternatives to directly installing and using the full Linux distribution of your choice on real computer hardware. One alternative that does not involve the use of a full-featured Linux distribution, is to utilize stripped down, easy to use (already installed) systems, either locally or in the cloud.

    If you are using recent Microsoft Windows versions, you can take advantage of [Windows Subsystem for Linux (WSL)](https://docs.microsoft.com/en-us/windows/wsl/about). WLS2 is the newer version, with enhanced capabilities and based on a subset of the Hyper-V hypervisor.

    The advantage of using WSL/WSL2 is that you do not need to run either a "dual-boot" system (Windows + Linux), nor install any third-party software, such as VMware Workstation Player or Oracle VirtualBox. However, you will only have command-line access to a Linux-like system, without the use of graphical interfaces and programs.

    Another alternative to having a physical Linux system is to use one hosted in the cloud. Probably the easiest path is to take advantage of [Amazon Web Services (AWS)](https://aws.amazon.com/free/?all-free-tier.sort-by=item.additionalFields.SortRank&all-free-tier.sort-order=asc&awsf.Free%20Tier%20Types=*all&awsf.Free%20Tier%20Categories=*all), which offers a wide range of virtual machine products (instances) for remote users to access in the cloud.

    In particular, you can use the AWS Free Tier account level for up to a year, and the simulated hardware and software choices available may provide most of what you need to gain experience with Linux. You can download a helpful [guide](https://training.linuxfoundation.org/cm/prep/aws.pdf?_gl=1*oin0sa*_ga*MjAzMzkzMTEwOC4xNzAwNTkxMDU0*_ga_EMX7DDZMX4*MTcwMTExMDgyNC40LjEuMTcwMTExNDI0Mi42MC4wLjA.) we have prepared to help you experiment with the AWS free tier.

    However, note that like WSL/WSL2, AWS does not give access to a graphical desktop, and you will not be able to easily use graphical applications, and as such, you will not be able to perform tasks which require their use.

- **Why Use Virtual Machines instead of AWS and WSL?**

    Whatever host operating system you use (i.e., Windows, Linux, MacOS, etc.), the freely available hypervisors (VMWare Workstation Player, Oracle Virtual Box, etc.) will enable you to run a full Linux distribution with a complete graphical interface, and will provide you the ability to do all kernel-related functions, such as adding device drivers, re-configuring, re-compiling, etc.

    In most cases, it will not take more time to install one of these programs and install a Linux VM with it than to set up and use either AWS or WSL. Typically, no more than half an hour is needed. Virtual Machines are strongly preferred for use in this course, as you will be able to get the full experience the course is designed for, rather than a truncated one without GUI interfaces and applications.

- **Download the Install Image**

    One of the first tasks is to select a Linux distribution to install. Ubuntu is very popular, so it will be used here. First, we need to download the installation DVD/USB image. We will go ahead and download [Ubuntu 20.04](https://releases.ubuntu.com/20.04.3/ubuntu-20.04.3-desktop-amd64.iso).

    Once the file is downloaded to the local system, the installation can begin.
    - If you are installing directly onto your hardware, replacing the existing operating system, follow the instructions above to download the Ubuntu ISO and create the USB, then skip ahead to the ___"Install Ubuntu"___ section, skipping the creation of the virtual machine section, as it is not required.
    - If using a virtual machine, VMware Player or Oracle Virtual Box are popular choices. We will use VMware Player to keep it shorter. You can continue with the ___"Create a VMware Virtual Machine"___ section.

- **Create a VMware Virtual Machine**

    1. Click on "Create a New Virtual Machine" 
    2. Select the Ubuntu ISO image you downloaded earlier. You will use it to install Ubuntu 20.04 on your new VM. <br>Click Next.
    3. Select a location for VMware to place the virtual disks and configuration files.
    4. Name the Virtual Machine. <br>Then, click Next.
    5. Specify the storage size; a minimal OS will use less than 10G. You also have the option to split the VM's disk into smaller parts. Some find it more convenient to have one large file, rather than several smaller files. <br>Click Next.
    6. Confirm the settings, then start the creation and installation by clicking on Finish.


- **Install Ubuntu**

    If using physical hardware, the ISO file must be copied to a USB device of the appropriate size. This [Ubuntu Tutorial](https://ubuntu.com/tutorials/create-a-usb-stick-on-windows#1-overview) shows all the steps to create a bootable USB.

    Start the Linux installation process. Regardless if you are booting from a bootable USB or a virtual disk connected to an ISO file, the installation process is the same for installing Ubuntu. 

    **Follow the steps below to install Ubuntu 20.04 on your new virtual machine.**

    1.  After creating our VM, we are now ready to install Ubuntu 20.04.

    2.  The initialization of the install program will prompt you to choose the desired language for the installation process.

    3.  Next, select "Install Ubuntu from the available options. If you need extra time to study the selections, press the spacebar to stop the countdown.

    4.  Select the language you want to have on the system that is being installed. Then, click on Continue.

    5.  Now, you must select the desired keyboard layout. Click Continue.

    6.  Next, select the installation type: Minimal or Normal. We are using Normal in this instance. It is typical to apply updates during install. In this case, deselect updates, as they will be applied in a later section. If the disk has been used previously for another purpose, select to erase and reinstall. Click Install Now.

    7.  Now it's time to choose the desired timezone. Then, click Continue.

    8.  Add your hostname and user ID. Click Continue.

    9.  The installation begins. This is a great opportunity to take a break, as the process will take a while!

    10. Once the installation process completes, it will ask you to restart your computer. Click Restart Now.
    
    11. Once your computer restarted, log in. You will see the default desktop. Congratulations on successfully installing Ubuntu!

## Backup
- **Backing Up a Linux System**

    There are many methods to create a backup of a Linux system. The most important aspect is backing up the data and the configuration files for various services. 
    
    The configuration files are generally located in the ```/etc``` directory. 
    The user data normally stored in ```/home``` should also be backed up. 
    Backing up the ```/boot``` directory may be useful.
